# Сводка для экосбора

Локальная страница для подготовки сводных данных из статистических форм ФТС и отчётов «Честного знака» (ЧЗ). Страница показывает данные для проверки и формирует Excel-файл. Это вспомогательный инструмент: перед использованием результатов сверяйте их с исходными документами.

## Как открыть

1. Сохраните все файлы проекта в одной папке, сохранив расположение папки `examples`.
2. Дважды нажмите `index.html`. Страница откроется в браузере Microsoft Edge или Google Chrome.
3. Для проверки можно загрузить **вымышленные** файлы из папки `examples`. Это учебные примеры, а не настоящие документы.

Страница обрабатывает документы на вашем компьютере: отдельно установленный сервер, учётная запись и отправка документов на сайт не нужны. Данные загруженных документов хранятся только в открытой странице; после её обновления их нужно загрузить снова. Скачанный Excel сохранится там, куда браузер обычно помещает загрузки.

## Как подготовить сводку для нового клиента

1. Получите у клиента статистические формы ФТС в PDF и/или отчёты ЧЗ в XLS или XLSX за нужный период. В приложении ФТС и ЧЗ можно загрузить вместе или по отдельности.
2. Откройте `index.html`, нажмите **«Выбрать файлы»** и выберите документы либо перетащите их в область загрузки. Для следующего клиента сначала нажмите **«Очистить всё»**.
3. Проверьте сообщения страницы. Убедитесь, что все документы относятся к нужному клиенту и периоду, а повторы и листы, которые страница пропустила, действительно не нужны. Сравните число строк в выгрузке ЧЗ с указанным в самом отчёте и проверьте предупреждение об ограничении выгрузки.
4. На вкладке **«ФТС · строки»** сверьте коды ТН ВЭД, вес нетто и количество с исходными формами. Страница берёт вес нетто из графы 16, количество в штуках — из графы 18 при коде единицы 796. Пропущенное значение не считается нулём. На вкладке **«ФТС · сводка»** показаны итоги по кодам и за весь загруженный набор документов. Страница не отбирает статформы по периоду автоматически: загружайте только нужные формы.
5. На вкладке **«ЧЗ · строки»** проверьте даты ввода, наименования, количество и признак условного ввода. В расчёт включается тип ввода **«Произведено в РФ»**; другие типы, например «Маркировка остатков», исключаются. В своде ЧЗ товары группируются по году и приведённому наименованию: цвет, размер и артикул не учитываются, обозначения мужские, женские, для девочек и для мальчиков сохраняются. Алгоритм использует текстовые правила, поэтому проверьте спорные наименования по исходным строкам и не считайте автоматическую группировку классификацией товара.
6. Нажмите **«Скачать Excel»** и откройте файл. На листе **«ЧЗ свод за год»** заполните код ТН ВЭД и вес единицы в килограммах: в отчётах ЧЗ эти данные не определяются автоматически. Общий вес строки рассчитает Excel. Если у объединённых вариантов разный вес, используйте средневзвешенный вес по фактическому количеству каждого варианта. Проверьте, что один код ТН ВЭД подходит всем товарам группы. Итог веса за год появится после заполнения веса по всем строкам года.
7. Сверьте суммы и исходные строки до подготовки отчётности. Сохраните готовый файл в папку клиента **вне папки проекта и репозитория**.

### Ограничения

* Формат PDF должен содержать текст. Скан без распознанного текста не будет обработан; примените распознавание текста и проверьте результат вручную. Расположение полей в форме также должно быть похоже на поддерживаемые примеры; ошибки и пропуски проверяйте по оригиналам.
* Совпадающие отчёты и статформы страница старается не учитывать дважды. Частично пересекающиеся или изменённые отчёты могут не распознаться как повторы: проверяйте периоды и состав.
* Если в отчёте ЧЗ больше строк, чем выгружено из системы, получите остальные данные отдельной выгрузкой и проверьте пересечения. Группировка не проверяет законность кода ТН ВЭД и не определяет принадлежность товара к группе экосбора.
* Если вес или количество не извлечены, итог для затронутого показателя отмечается как отсутствующий. Страница не устанавливает недостающие значения самостоятельно.

## Проверка на вымышленных данных

Загрузите оба файла из `examples`:

* В примере ФТС две строки с общим весом **20 кг**; количество второй строки отсутствует.
* В примере ЧЗ три строки типа «Произведено в РФ» на **27 шт.** Два размера брюк для девочек объединяются в **20 шт.**, брюки для мальчиков показываются отдельно — **7 шт.** Ещё одна строка с типом «Маркировка остатков» исключается.

## Как сохранить проект в приватном репозитории GitHub

1. Войдите в GitHub и откройте [создание репозитория](https://github.com/new). Введите название, например `ecosbor-summary`.
2. Выберите **Private** и создайте репозиторий. Для простоты не добавляйте новый README при создании: он уже есть в проекте. Инструкция GitHub: [создание репозитория](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository).
3. На странице созданного репозитория нажмите **Add file → Upload files**. Загрузите **содержимое только подготовленной папки проекта**: файлы страницы, `README.md`, `.gitignore`, уведомления о библиотеках и папку `examples` с двумя вымышленными примерами. Если папка не перетаскивается, сначала загрузите файлы из корня проекта. Затем создайте папку: нажмите **Add file → Create new file**, введите имя `examples/.gitkeep` и сохраните файл. Откройте появившуюся папку `examples` и через **Add file → Upload files** добавьте в неё два вымышленных примера.
4. До нажатия **Commit changes** внимательно проверьте список загружаемых файлов. В нём не должно быть реальных статформ, отчётов, результатов клиентов или других документов из соседней рабочей папки. `.gitignore` помогает при работе через Git, **но не фильтрует файлы, загружаемые вручную через сайт GitHub**.
5. Нажмите **Commit changes**. Проверьте, что на странице репозитория указан статус **Private** и структура файлов сохранена. Инструкция GitHub: [добавление файлов через браузер](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository?platform=windows).

Папка проекта подготовлена как отдельная копия. Изменения, сделанные в другом `index.html` или другом `eco-page.js`, не попадут в эту копию автоматически. Перед следующей загрузкой изменений обновите файлы проекта, проверьте их и список отправляемых файлов.

## Файлы проекта и библиотеки

* `index.html`, `eco-page.js`, `eco-page.css` — страница и её логика.
* `xlsx.full.min.js`, `pdf.min.js`, `pdf.worker.min.js` — локальные библиотеки чтения и создания файлов. Их нужно хранить рядом с `index.html`.
* `examples/` — только два вымышленных учебных файла.
* `.gitignore` — список разрешённых к добавлению через Git файлов; другие файлы по умолчанию игнорируются.
* `THIRD_PARTY_NOTICES.md`, `APACHE-2.0.txt` — сведения о сторонних библиотеках и их лицензии.
